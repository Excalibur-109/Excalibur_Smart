RHI/D3D11

D3D11 后端：immediate context 状态机

RHID3D11 用 Direct3D 11 的 COM 对象和 immediate context 实现同一份 RHI。它与 Vulkan/D3D12 最大的差异是：没有显式 command list、资源 layout 或完整 PSO；绘制时需要把各个状态对象逐项设置到 context。

构建状态该后端有完整源码，但当前根 CMakeLists.txt 未把 RHID3D11.cpp 加入 RHI 静态库。并且它依赖 Windows、D3D11、DXGI 与 D3DCompiler，只能在合适的 Windows 目标上链接。

初始化与原生句柄

RHID3D11Desc 包含通用 RHIBackendDesc、RHID3D11SurfaceDesc::hwnd、D3D_DRIVER_TYPE、最小 D3D_FEATURE_LEVEL 和 allowWarpFallback。Core 实现创建 DXGI factory/adapter、ID3D11Device 与 ID3D11DeviceContext，检查 feature level 和 required RHI feature；失败时可选择 WARP。

RHID3D11NativeHandles 对外提供 IDXGIFactory1*、IDXGIAdapter1*、ID3D11Device*、immediate context、实际 feature level 和 HWND。

格式与资源模型

RHID3D11Private.inl 用 toDxgiFormat/fromDxgiFormat 处理大部分 RHIFormat。D3D11 的深度资源有一个关键细节：资源往往创建为 typeless DXGI_FORMAT，随后 DSV 解释为深度格式、SRV 解释为可采样 R 格式。这是同一张 shadow map 可写深度又可采样的基础。

RHI 调用D3D11 对象实现要点
CreateBufferID3D11BuffermemoryUsage 映射 D3D11_USAGE_DEFAULT/DYNAMIC/STAGING；Vertex/Index/Uniform/Storage 映射 bind flags。
CreateTextureID3D11Texture1D/2D/3Dusage 决定 SRV/UAV/RTV/DSV bind flags；深度使用 typeless resource format。
CreateTextureViewID3D11ShaderResourceView、RenderTargetView、DepthStencilView、UnorderedAccessView同一个 RHITextureViewResource 可按纹理 usage 持有若干 D3D11 view。
CreateSamplerID3D11SamplerStatemin/mag/mip 线性组合、comparison、anisotropic 都由 toD3DFilter 选择具体 D3D11_FILTER。
CreateShaderModuleVS/HS/DS/GS/PS/CS COM shader输入可为 HLSL source/file 或已编译 DXBC；调用 D3DCompile，按 stage 创建对应 shader 对象。
CreateBindSetLayout逻辑 layoutD3D11 没有 descriptor set layout 原生对象；保留 RHI entries 供后续绑定时验证和路由到 shader slots。
CreateBindSet已解析的 CB/SRV/UAV/sampler binding资源不复制到单一 descriptor set；frame 录制时按 visibility/binding 逐项调用 context 的 *Set* 方法。
CreatePipelineLayout逻辑 layout用于保持绑定模型一致；D3D11 没有 D3D12 root signature 对等物。

格式限制ETC2 与 ASTC 在 toDxgiFormat 中映射为 DXGI_FORMAT_UNKNOWN；S8_UInt 也没有直接 D3D11 映射。创建使用这些格式的纹理会失败。

绑定模型：为什么 D3D11 看起来不同

Vulkan 把一组资源预写进 VkDescriptorSet，D3D12 把 descriptor table 指向 shader-visible heap；D3D11 则是在 draw/dispatch 之前将资源按 stage 与 slot 直接绑到 immediate context。RHI 的 BindSet 仍然有价值：它把“某个 binding 放了什么资源、对哪个 stage 可见”的数据组织在一起，后端可以统一验证和应用。

// 概念上的 D3D11 应用过程
applyPipeline(pipeline);        // IA layout/topology, VS/PS..., raster/depth/blend state
applyBindSet(bindSet);          // VSSetConstantBuffers / PSSetShaderResources / ...
context->DrawIndexed(...);      // 命令立即进入 immediate context

Uniform buffer 偏移有明确限制：当 RHIResourceBinding 请求 offset 时，代码会报告“D3D11 constant buffer offsets require D3D11.1 and are not implemented”。Storage raw buffer 的 offset 与 size 必须 4-byte 对齐。

管线：状态组合而非单个 PSO

CreateGraphicsPipeline 创建 input layout、vertex/hull/domain/geometry/pixel shader、rasterizer state、depth-stencil state、blend state，并把 topology、stencil reference、blend constants、sample mask 存入 PipelineResource。frame 中的 applyPipeline 逐项绑定它们。至少需要 vertex shader；向 graphics pipeline 放 compute/task/mesh 等非图形 stage 会失败。

CreateComputePipeline 只保存 ID3D11ComputeShader。CreateQueryPool 预创建一组 ID3D11Query，支持 Timestamp、Occlusion、PipelineStatistics 的对象创建，但 RenderGraph query workload 当前未录制。

RenderGraph 帧路径

Frame 实现处理 uploads、导入/瞬态 graph 资源、计划中的依赖、RTV/DSV 附件、viewport/scissor 和 immediate context 上的 draw/indexed draw/dispatch。资源状态在此后端主要作为逻辑状态追踪和 graph 依赖依据，而不是 Vulkan/D3D12 那种 explicit resource barrier。

内容状态说明
buffer/texture uploads已实现校验目标和数据范围，使用 D3D11 更新/拷贝路径。
buffer copy已实现受 graph 计划顺序约束。
Raster attachment、clear、draw、indexed draw已实现绑定 OM RTV/DSV，应用 pipeline 与 bind sets。
compute dispatch已实现应用 compute shader 与资源绑定。
texture copy/blit/mipmap未实现RenderGraph workload 明确抛错。
query/indirect workload未实现对象可创建不表示命令录制已实现。
workload 显式 barriers拒绝必须使用 graph reads/writes 声明依赖。

官方模型补充：上下文、用法与 CPU 访问

D3D11 的 immediate context 是设备的默认命令入口，调用会按 context 状态形成命令流；驱动何时把工作送往 GPU 对应用不是显式 command queue 契约。官方也支持 deferred context：它只录制命令，调用 FinishCommandList 得到 command list，再由 immediate context ExecuteCommandList 执行。当前后端只使用 immediate context，因此 RHI 的 graph pass 不是并行 D3D11 command list 录制。

D3D11_USAGE、CPU access flags、bind flags 和 misc flags 是一组受约束的组合，不是任意拼接。典型规则是：DEFAULT 由 GPU 读写、CPU 不直接 Map；DYNAMIC 适合 CPU 高频写入并通常用 WRITE_DISCARD；STAGING 用于 CPU/GPU 数据交换，不能绑定给 pipeline。仓库的 toD3DUsage 依照 memory usage 选用这些模式；上层不能把“可映射”误解为可作为任意 shader resource 或 render target。

D3D11.1 才提供带 first constant/num constants 的 constant-buffer range 绑定。当前后端明确未实现 uniform buffer offset，因此需要为每个偏移区间建立独立 CB，或先扩展到 D3D11.1 的 *SetConstantBuffers1 路径。

官方模型补充：视图绑定与读写冲突

D3D11 没有 Vulkan layout 或 D3D12 resource barrier，但不表示可以同时读写同一子资源。运行时会阻止同一资源子资源同时作为输出绑定点（RTV/DSV/UAV）与输入 SRV；发生冲突时，相关绑定可能被自动置空并在 debug layer 报警。RenderGraph 的依赖排序只能安排 pass 顺序，不能替代将旧 SRV/UAV 从各 shader stage 解绑，再将资源作为 render target、depth target 或 UAV 绑定的职责。

因此，applyBindSet 前后应把资源角色看作状态机：先解除冲突的输入/输出 view，再绑定新的 view，最后 draw 或 dispatch。当前 frame 路径会调用 VSSetShaderResources、PSSetShaderResources、CSSetUnorderedAccessViews 和 OMSetRenderTargets；建议使用 D3D11 debug layer 验证同一 texture 在相邻 pass 的绑定清理是否完整。

官方模型补充：DXGI 呈现

交换链属于 DXGI。窗口尺寸改变时，应用必须先释放对 back buffer 的所有引用并解绑 output，再调用 ResizeBuffers，随后重新取得 buffer 并创建 RTV。Present 的 sync interval 控制垂直同步；tearing 只适用于兼容的 flip-model swapchain、允许 tearing 的创建 flag 和对应 Present flag。当前实现包装第 0 个 back buffer，窗口 resize/recreate 是后续必须补齐的生命周期路径。
