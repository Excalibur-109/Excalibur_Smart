UI 系统：把控件变成一个 RenderGraph pass

UI 位于 RHI 之上，只使用 RHIDevice、RHIFramePacket 和 RHIRenderGraph 的公开接口。它不需要修改 Vulkan、D3D11 或 D3D12 的资源表与命令录制代码，因而可作为独立模块复用。

核心结论UI 的遮挡由 painter order（layer 加提交顺序）决定，透明度由普通 source-alpha 混合决定，深度测试和深度写入都关闭。UI pass 使用 Load 读取已经画好的 PBR backbuffer，再用 Store 把合成结果交给 Present。

1. 一帧的生命周期

Win32 WndProc 更新 InputState
        ↓
BeginFrame(extent, input)
        ↓
Panel / Text / Button / Image / SliderFloat（立即生成 CPU 顶点）
        ↓
AppendUploads(frame)       上传顶点和白色 1×1 纹理
ImportResources(graph)     注册 imported buffer/texture
AppendPassReads(uiPass)     声明 shader-read / vertex-input
AppendDraws(uiWorkload)     layer 排序并生成 draw
        ↓
RenderGraph: ShadowMap → OpaquePBR → UI → Present

BeginFrame 会清空上一帧的顶点、draw 列表和外部图片名称。控件函数只做 CPU 侧记录，不立即访问 GPU；因此调用顺序简单、可读，也不会在同一帧创建大量短命原生对象。activeSlider_ 是唯一跨帧状态，用于保证鼠标按住滑块拖动时，鼠标离开控件矩形仍能继续修改数值。

2. 基本数据结构

类型含义实现细节
ColorRGBA 归一化颜色和不透明度作为顶点色；片元阶段与纹理采样值相乘。
Rect客户区像素矩形命中测试直接使用像素；提交四边形时除以 viewport 宽高。

3. 图层、遮挡与透明度

每次绘制都生成一个 DrawItem。提交时增加单调递增的 order；AppendDraws 按 layer 升序、再按 order 升序稳定排序。因此规则是：

  • layer 较小的控件先绘制；layer 较大的控件后绘制并覆盖前者。
  • 同一 layer 中，后调用的控件覆盖先调用的控件。
  • 覆盖不是深度测试意义上的遮挡，而是颜色写入顺序；半透明控件仍会看到下面的颜色。

管线的混合状态为 srcAlpha, oneMinusSrcAlpha。RGB 使用 src.rgb * src.a + dst.rgb * (1-src.a)，alpha 使用同样的覆盖关系。关闭深度测试是必要的：PBR 场景的深度值不能决定一个屏幕空间面板是否可见。

4. 控件实现

Panel 与白色纹理

Panel 调用 AddQuad，绑定一张初始化为 FF FF FF FF 的 1×1 RGBA8 纹理。采样值恒为白色，所以矩形外观完全由顶点色决定。这样所有控件共用一个 fragment shader 和一个 pipeline，不需要单独的“纯色 PSO”。白纹理在第一次 AppendUploads 时上传，之后由 staticUploadsPending_ 防止重复上传。

Text 与 TextBox

内置字体是 5×7 点阵：每个字符保存 7 个五位 bit mask；亮 bit 展开为一个小 quad，字符之间保留一列间距。它不依赖 Windows 字体或 GPU 字体 atlas，因此三个后端输出一致。当前字库覆盖英文大写、数字和少量符号，未知字符显示问号。TextBox 是 Panel 加 Text 的组合控件，当前是显示型文本框，不处理键盘输入、光标和选区。

Image

Image 先画稍大的蓝色边框，再以 layer + 1 画实际纹理。外部纹理名称被记录到 externalTextureNames_，稍后作为 UI pass 的 shader-read 资源声明。BindSetForImage 用 (texture, view) 查找缓存；同一张材质贴图重复预览时不会创建新的原生 descriptor set 或 descriptor table。

Button 与 SliderFloat

Button 根据 Rect::Contains 改变悬停颜色，在“命中 + leftButtonPressed”时返回一次性事件。SliderFloat 将鼠标 x 投影到 track 的 [0,1]，映射到 [minimum, maximum] 并用 round(value / step) * step 量化；它返回本帧 value 是否发生变化。

5. RenderGraph 接入

Context 创建的顶点缓冲和白纹理位于 RenderGraph 外部，故 ImportResources 将其标记为 Imported 并提供 externalHandle。RenderGraph 只负责本帧的状态和依赖，不负责这些对象的销毁。PBRDemo 对外部材质预览纹理也做同样的 import。

声明资源状态用途
UI.VerticesVertexBuffer / VertexInput顶点输入阶段读取 UI 几何。
UI.White 与图片ShaderRead / FragmentShader片元阶段采样白纹理或材质纹理。
BackBufferColorAttachmentUI pass 使用 Load，保留 OpaquePBR 的颜色。
DepthDepthStencilAttachment使用 Load 保留深度，但 UI PSO 不测试也不写入它。

这套做法把“图形资源状态”交给 RenderGraph，把“控件排序和顶点内容”留在 UI 自己内部，边界清晰：增加 Button 不需要改 RHIVulkanFrame.inl、RHID3D11 或 RHID3D12。

6. Win32 输入与坐标

PBRDemo 的 WindowProcedure 接收 WM_MOUSEMOVE、WM_LBUTTONDOWN 和 WM_LBUTTONUP，将 LOWORD/HIWORD(lParam) 转为客户区像素，写入 uiInput_。每次 BuildUI 完成后清除 Pressed/Released 边沿，下一帧只保留 Down。右键相机观察使用独立的鼠标捕获状态，不会把右键误传给 Button。

GLSL 与 HLSL 的 Y 公式相反：Vulkan shader 使用 y * 2 - 1，D3D 使用 1 - y * 2。两份 shader 都把 UI 的左上角像素映射到屏幕左上角，UI 控件代码不需要知道后端。

7. 文件与限制

RHI/UI/RHIUI.hpp

公开数据结构和控件/RenderGraph 接口。

RHI/UI/RHIUI.cpp

点阵字体、资源创建、顶点上传、排序和销毁。

RHI/UI/shaders/

Vulkan GLSL 与 D3D 共享 HLSL 入口点。

  • 字体目前主要支持英文、数字和少量 ASCII 符号；中文需要接入 glyph atlas 或外部字体栅格化。
  • TextBox 目前只是显示控件；完整编辑需要键盘消息、文本插入、光标和剪贴板。
  • Image 面向 2D texture view，不处理 cubemap、视频帧或自动 mip 生成。
  • 单帧顶点容量是 65536；复杂编辑器应改成分块 buffer 或动态增长策略。
