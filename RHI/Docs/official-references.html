Vulkan：Khronos Registry 与 Vulkan Guide

Vulkan 的术语最容易在“对象创建”与“GPU 执行”之间混淆。建议先用 Guide 建立资源和同步模型，再回到 Specification/Reference 查 exact valid usage；最后对照 Vulkan 后端页 的 RHIVulkanResources.inl、RHIVulkanFrame.inl 与 RHIVulkanSyncSwapchain.inl。

  • Vulkan Specification: Fundamentals
    对象、instance/device 作用域和基础有效性规则。用来审查创建/销毁顺序和父对象生存期。
  • Vulkan Specification: Memory
    memory requirements、memory type、allocate/bind 与 mapped memory 的规则。对应当前“每资源独立分配”的实现取舍。
  • Vulkan Guide: Memory Allocation
    设备内存选择、子分配和常见 allocator 思路。适合在读懂 vkAllocateMemory 直连实现后继续阅读。
  • Vulkan Specification: Synchronization and Cache Control
    stage/access、execution dependency、memory dependency、queue-family ownership 与 layout transition 的准确定义。
  • Vulkan Guide: Synchronization Examples
    将 upload、attachment、compute 与 present 场景拆成可核对的 barrier 模式。适合逐项检查 RenderGraph transition。
  • Vulkan Specification: Resource Descriptors
    descriptor set layout、pool、allocation、update 与命令缓冲引用规则。对应 CreateBindSetLayout/CreateBindSet。
  • Vulkan Guide: Descriptor Sets
    descriptor set、pool 与替代绑定模型的实用说明，便于和 D3D12 descriptor heap 横向比较。
  • Vulkan Reference: vkAcquireNextImageKHR，vkQueuePresentKHR
    WSI acquire/present 的返回值和 semaphore 约束。重点确认 out-of-date/suboptimal 与 binary semaphore 使用。
  • Vulkan Reference: VkSemaphoreTypeCreateInfo
    binary/timeline semaphore 的类型和 initial value。对应 frame timeline 与交换链 acquire semaphore 不能混用的原因。

D3D11：Microsoft Learn

D3D11 依然有严格资源和绑定规则，只是许多状态转换由 runtime/driver 隐式处理。阅读时，重点不要把“没有显式 barrier”理解成“同一资源可以随意同时读写”。对照 D3D11 后端页 时，特别查看 RHID3D11Frame.inl 中的 shader-resource、UAV 和 render-target 绑定。

  • Introduction to Resources in Direct3D 11
    资源、view、bind flag 和 usage 的总体模型。用于审核 RHI memory usage 与 D3D11 resource 描述的映射。
  • Introduction to Render Targets in Direct3D 11
    render target、depth-stencil 和 view 的使用边界，适合阅读 OMSetRenderTargets 路径前查阅。
  • Introduction to Multithreading in Direct3D 11
    immediate/deferred context 的职责和多线程录制模型；当前后端只走 immediate context。
  • ID3D11Device::CreateDeferredContext，ID3D11DeviceContext::FinishCommandList
    deferred context 的 API 层生命周期。用于区分“可选并行录制能力”和仓库现在的实际路径。
  • D3D11_USAGE，D3D11_CPU_ACCESS_FLAG
    DEFAULT/DYNAMIC/STAGING 与 CPU map 权限的组合约束。对应 toD3DUsage。
  • ID3D11DeviceContext::OMSetRenderTargets
    输出合并阶段的绑定规则及读写冲突限制。用于排查 SRV/RTV/DSV/UAV hazard。
  • IDXGISwapChain::ResizeBuffers
    resize 前释放 back-buffer 引用的硬性要求。对应当前 swapchain 后续应补齐的重建路径。

D3D12：Microsoft Learn

D3D12 把同步、资源状态、descriptor heap 和 command allocator 生命周期交回应用管理。将 D3D12 后端页 与这些资料一起读，可以明确区分当前实现已做的显式 transition 与尚未接入的多队列、placed resource/aliasing path。

  • Command Queues and Command Lists
    queue、command allocator/list、Close/Reset/Execute 的基本关系。对应 frame 的 reset/record/submit 生命周期。
  • Fences
    CPU-GPU 与 GPU-GPU 同步的 fence signal/wait 模型。用于理解 internal fence 与 frames in flight。
  • Descriptor Heaps Overview
    CPU-visible/shader-visible heap、heap switch 和 descriptor table 的约束。对应 bind set 的 CPU 到 GPU descriptor 路径。
  • Root Signatures
    descriptor table、root descriptor、root constants 的 ABI 和代价。对应 pipeline layout 的 root signature 生成。
  • Using Resource Barriers to Synchronize Resource States
    transition/UAV/aliasing barrier、COMMON state 与 promotion/decay。用于核对 RenderGraph state 推导。
  • Memory Aliasing and Data Inheritance
    placed resource 的内存重叠及 aliasing barrier。对应 graph alias slot 尚未落地为 D3D12 实体的差距。
  • Swap Chains，IDXGISwapChain::ResizeBuffers
    flip model、back buffer、present 和 resize 生命周期。对应当前 FLIP_DISCARD swapchain。

从官方模型回到本仓库

  1. 先在 资源与枚举 明确 RHI 声明的意图，例如 sampled、storage、attachment 与 resource state。
  2. 在 RenderGraph 确认每个 pass 的 reads/writes、生命周期和 transition 是否完整。
  3. 针对目标后端使用本页对应的官方资料检查原生约束，再回到 Vulkan、D3D11 或 D3D12 判断当前代码是否已经落实。
  4. 对于未落地的能力，文档会标注“未实现”或“未接入”；不要从某 API 概念存在反推本项目的 frame 路径已经支持。
