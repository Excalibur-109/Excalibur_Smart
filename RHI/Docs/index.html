Source-guided documentation

渲染抽象如何落到三套图形 API

这套文档以仓库中的实际实现为中心。先理解 RHIDefinitions.hpp 的通用语言，再沿着 Device、RenderGraph、资源、管线、帧提交的顺序进入 Vulkan、D3D11 与 D3D12。

当前状态文档会明确标注已实现、有限制和未实现部分。当前 CMake 的 RHI 静态库只列入公共定义、Device、RenderGraph 与 RHIVulkan.hpp；三套后端的 .cpp 虽在仓库中，但尚未加入该目标。因此本学习材料描述的是已有源码，而不是宣称它们已被当前库链接和运行。

推荐学习路线

1. 抽象词汇。阅读“资源与枚举”，理解一个逻辑句柄为何可以映射为不同 API 的资源、视图、绑定与管线。
2. 设备边界。阅读 Device，分清通用初始化请求和每个后端的窗口/扩展/适配器细节。
3. 图调度。阅读 RenderGraph，掌握 pass 依赖、生命周期、裁剪、别名和状态转移怎样在提交前被计算。
4. 选择一个后端深挖。建议先 Vulkan，再 D3D12，最后用 D3D11 对照理解隐式状态模型。
5. 横向复盘。通过后端对比页检查同一 RHI 描述在三个原生 API 中分别落成什么对象和命令。

每个后端的源码分段

三份 .cpp 都按相同顺序包含七个实现段。这不是七个独立库，而是为了让一个类的实现按职责展开，便于对照阅读。

RHIVulkan.cpp / RHID3D11.cpp / RHID3D12.cpp
  ├─ *Private.inl       映射、辅助函数、Impl 资源表
  ├─ *Core.inl          Instance/Device/Adapter/Queue 初始化
  ├─ *Resources.inl     Buffer、Texture、View、Shader、BindSet、Layout
  ├─ *Pipelines.inl     Graphics / Compute pipeline 与 QueryPool
  ├─ *SyncSwapchain.inl 同步对象、Swapchain、Acquire/Submit/Present
  ├─ *Frame.inl         FramePacket、RenderGraph 计划、命令录制
  └─ *Destroy.inl       句柄资源的逆序释放

开始前的三个原则

  1. 句柄不是原生指针。RHIHandle<Tag> 只保存 1-based 逻辑 ID；后端在 Impl 的资源表中找到真实对象。
  2. 资源与视图分开。RHITexture 表示存储，RHITextureView 表示对 mip、layer、aspect、格式解释后的访问窗口。对 Vulkan/D3D 都是关键概念。
  3. 资源状态由使用驱动。创建描述的 initialState 是意图；显式 API 的真实状态需要在命令路径中用 barrier 达成。RenderGraph 通过 reads/writes 统一推导这种转换。

入口页

资源与枚举

所有强类型句柄、格式、状态、同步、绑定、管线、帧 workload 与 RenderGraph 描述的完整索引。

Device

统一门面的设计意图、创建参数与当前尚未完成的工厂实现。

RenderGraph

从声明图得到拓扑序、转移、生命周期和 alias slot 的过程。

Vulkan

VkInstance 到 vkQueuePresentKHR，及 descriptor set、dynamic rendering 的具体落点。

D3D11

COM 资源和 immediate context 的逐项状态绑定模型。

D3D12

ID3D12Resource、root signature、PSO、descriptor heap 与 fence。

PBR Demo

从 Win32 HWND、stb_image、材质/天空盒到 ShadowMap、PBR、UI、Present 的完整运行链路。

UI 系统

不改 RHI 核心的即时模式控件、图层排序、透明混合、图片预览与 RenderGraph 接入。
